# 비공개 학교 배포 인수 조건

이 파일은 배포 완료 증명서가 아닙니다. 소유한 서버의 HTTPS 주소로 MASTER와 학생이 각자 접속한 후 결과를 기록합니다. 두 사용자가 각자의 컴퓨터에서 `localhost`에 접속하면 서로 다른 서버를 가리킵니다. **동일한 `https://소유한-학교-도메인`**을 공유해야 합니다.

## 호스트 준비와 사전 점검

1. 검토/승인된 커밋에서 이미지를 빌드하고 immutable digest 또는 로컬 이미지 ID를 확보합니다. 예: `docker image inspect pixel-class:reviewed --format '{{.Id}}'`. 이미지/원본 DB/이전 배포 설정을 보존합니다.
2. `deploy/compose.env.example`을 저장소 밖으로 복사해 0600으로 제한합니다. 도메인, 이미지, 비밀 파일 경로를 채웁니다. 기본 루프백 주소를 원격 접근이 필요한 VPN 인터페이스로 변경하거나, 방화벽을 설정한 호스트의 외부 바인딩으로 변경합니다.
3. [운영 절차](README.md)의 부트스트랩/별도 접근 암호 파일을 준비합니다. 앱이 읽는 secret은 UID 1000, 0400 권한이 필요합니다. 실제 키/암호를 명령 인자, Git, 채팅에 넣지 않습니다.
4. `npm run deploy:check -- --env-file /srv/pixel-private/compose.env`를 실행합니다. AI를 연결할 때만 `--ai`를 더합니다. 이 명령은 해석된 Compose 구성과 비밀 파일 메타데이터를 읽고, 앱 UID의 일회성 검증 컨테이너에서 서버 전용 secret을 검사합니다. 검증 컨테이너는 네트워크·학교 DB 연결이 없고 읽기 전용이며, 설정 모듈만 실행한 뒤 제거됩니다. 복원 DB 경로나 부트스트랩 secret 제거 override는 `--compose-file /private/override.yaml`로 같은 순서로 추가합니다. 실제 마운트된 secret만 검사하므로 최초 MASTER 등록 뒤 부트스트랩 파일을 제거한 기존 학교도 확인할 수 있습니다. DB에 MASTER가 존재하는지는 별도 인수 조건입니다. 앱 서비스 시작/삭제/외부 게시를 수행하지 않고, 구성 성공도 DNS·공인 TLS·접속 성공을 의미하지 않습니다. Docker daemon과 Compose가 필요합니다.
5. 업데이트 전에 온라인 백업을 만들고 외부의 암호화된 보관처로 복사합니다. 새 파일로의 복원과 과거 세션 철회를 확인합니다. DB 볼륨을 지우는 `down --volumes`는 운영에서 금지합니다.
6. 실제 시작: `docker compose --env-file /srv/pixel-private/compose.env up -d --no-build --wait`. AI 사용 시 두 명령에 `-f compose.yaml -f deploy/compose.ai.yaml`을 **항상 같은 순서로** 포함합니다. preflight도 같은 `--ai` 옵션을 사용합니다.
7. DNS와 80/443 방화벽, 공인 TLS 또는 조직이 신뢰하는 VPN TLS를 확인합니다. 앱 3001 포트는 게시하지 않습니다. 서비스/호스트 재시작 후 볼륨과 공인 인증서가 유지되는지 확인합니다.

## 두 컴퓨터에서 실제 인수

- 컴퓨터 A(MASTER), 컴퓨터 B(학생)가 공통 도메인으로 접속. 별도 접근 암호를 거친 뒤 각자의 앱 계정으로 로그인.
- MASTER 최초 등록→일회용 초대 링크 발급→학생 계정/캐릭터/책상 배정. 같은 초대의 재사용은 거부.
- 학생 프로젝트 생성/수정/새로고침→MASTER 질문/피드백→학생 알림과 내용 확인.
- MASTER가 UI에서 교안 업로드→학생의 원문 미리보기/다운로드. 학생 업로드 권한과 다른 학생 비공개 첨부는 거부.
- 두 사용자의 접속 표시/캐릭터 이동/채팅. Wi-Fi 변경/새로고침 후 재연결. 다른 출처의 요청/소켓과 로그아웃 후 세션은 거부.
- 휴학/권한 회수 시 접속을 제한하고 기존 프로젝트/자료를 보존. 복학 후 기존 데이터 확인.
- 모바일에서 입력/모달/터치 이동을 사용하고, 실제 사무용 노트북에서 로딩·이동·화면 전환을 확인.
- 브라우저를 닫은 뒤 유령 접속이 사라지는지 확인. 백업 실패/디스크 여유/프로세스 재시작/인증서 갱신 알림 담당자를 정함.

## AI 첫 연결: 최대 3회 소액 평가

- 서버에 프로젝트 전용 제한 키를 파일 secret으로 공급하고 사용 가능한 Responses 모델 ID를 지정합니다. 현재 저장소의 어떤 값도 실제 키/모델을 대신하지 않습니다.
- `AI_SCHOOL_DAILY_CALLS=3`, `AI_MAX_CONCURRENT=1`로 시작합니다. 기본 운영값은 60회/일·동시 2개이며, 사용자별 5회/분·20회/일·출력 1200토큰·30초 제한도 함께 적용됩니다. 실패한 제공자 호출도 횟수에 포함되고, 재시작/복원으로 한도가 초기화되지 않습니다.
- 입력은 프로젝트 문맥 6000자+최근 대화 합계 16000자(최대 10개)까지입니다. 글자 수는 토큰 수/달러 비용이 아닙니다. 제공자의 모델 제한·예산·알림·최신 단가를 별도로 설정하고, 알림이 즉시 강제 차단한다고 가정하지 않습니다.
- 민감정보가 없는 QA 프로젝트 하나에서 질문: **“처음 웹서비스를 만듭니다. 기록 입력과 목록만 필요합니다. API·서버·DB가 각각 필요한 이유와 오늘 할 한 가지를 쉽게 설명해 주세요.”**
- 실제 응답을 수동 평가: 한국어와 초보자 수준, 프로젝트 맥락, 여섯 안내 항목, 불필요한 기술 과잉 여부, 보지 않은 코드를 봤다고 주장하는지, 비밀키를 서버에 두도록 안내하는지. 실제 응답/제공자 usage·지연·사용액을 비공개 평가 기록에 남깁니다. 자동 키워드 검사만으로 품질 통과를 판정하지 않습니다.
- 최대 3회 이내 평가 후 허용 범위를 결정합니다. 비용/품질 이상 시 키 철회 또는 AI override 제거 후 앱 재생성으로 중지합니다. 제공자 오류는 제한/인증/시간 초과/네트워크를 구분해 확인하고 TLS 검증을 끄지 않습니다.

로컬 Docker의 독립 네트워크 클라이언트 2개와 Chromium 에뮬레이션은 이 절차를 돕는 사전 검증입니다. 실제 두 컴퓨터·공용 인터넷·물리 기기 인수를 대체하지 않습니다.
