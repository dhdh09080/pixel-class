# 지속 서버 배포 절차 (미배포)

현재 SQLite 저장소와 WebSocket을 사용하는 단일 서버 구성입니다. Vercel 정적 사이트 배포 대상이 아닙니다. Dockerfile과 Compose/Caddy 예시는 작성했지만 이 작업에서는 이미지 빌드, 실제 TLS 인증서 발급, 외부 배포를 실행하지 않았습니다.

1. Docker/Compose가 설치된 전용 호스트와 소유한 도메인을 준비하고 DNS를 호스트에 연결합니다. 80/443만 공개합니다.
2. 로컬에서 `npm run build`, `npm test`, `npm run test:e2e`를 통과시킵니다.
3. 호스트의 비밀 환경 설정에 `PIXEL_DOMAIN`, 무작위 `MASTER_BOOTSTRAP_KEY`를 설정합니다. 도메인에는 `https://`를 붙이지 않습니다. API 키는 필요할 때만 서버 전용으로 설정합니다. 비밀 파일은 저장소에 커밋하지 않습니다.
4. `docker compose config --quiet`로 변수와 구성을 확인하고 `docker compose up -d --build`로 시작합니다.
5. `https://지정한-도메인`에서 최초 MASTER를 등록합니다. 이후 부트스트랩 KEY를 환경 설정에서 제거하려면 Compose의 필수 값 검사도 조정합니다. 이미 있는 MASTER를 다시 생성할 수 없습니다.
6. 초대받지 않은 접근 거부, 타 학생 프로젝트 수정 거부, 개인 파일 접근 차단, 두 브라우저 이동/채팅, 서버 재시작 후 프로젝트 보존을 실제 호스트에서 다시 확인합니다.
7. 지속 볼륨을 정기 백업합니다. WAL DB를 실행 중에 단일 파일 복사로 백업하지 않습니다. 버전 업그레이드 전 일관된 백업과 복원 시험을 합니다.

Caddy가 TLS 종료와 WebSocket 업그레이드를 처리합니다. 앱은 외부 포트를 직접 열지 않고, 쿠키 Secure=true 및 PUBLIC_ORIGIN=https://도메인을 사용합니다. 건강 확인은 내부 `/api/health` 경로입니다. 단일 인스턴스용이므로 여러 앱 컨테이너를 같은 SQLite 볼륨에 붙여 확장하지 마세요.

로컬 인증에는 이메일 검증/비밀번호 복구/MFA가 없습니다. 이 예시는 공개 운영이 검증되었다는 뜻이 아닙니다. 실제 조직 운영 전 관리형 인증 전환과 별도 권한/보안 검토가 필요합니다. Supabase 전환 안내는 `supabase/README.md`를 확인하세요.
