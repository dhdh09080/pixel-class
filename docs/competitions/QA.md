# 경진대회 프런트엔드 검증 기록

실제 배포 여부 및 최종 전체 회귀 결과는 저장소의 최종 운영 보고서를 따른다. 아래 검증은 외부 Railway 운영 데이터와 분리된 임시 SQLite의 로컬 **production 빌드**에서 수행했다. 테스트에 실제 학생 개인정보를 사용하지 않았다.

## 구현과 검증

- MASTER: 반 생성·학생 배정, 반별 참가자 선택, 한국 시간 일정 입력, 초안 생성·개최·취소·보관, 결과 사전 집계·명시적 공개, 기한 연장, 심사 KEY 발급·취소·작품 범위·연결 만료 설정.
- STUDENT: 개인 프로젝트 선택, 소개서 템플릿 또는 HTML 원본, 결과물 URL/파일, 공개 대상 설명 및 재제출 시 재동의, 임시 저장·제출·철회, 버전과 서버 확인 일정 표시.
- 공개 경로 `/competition/:id`: 학교 Auth 초기화를 실행하지 않음. KEY는 fragment에서 읽고 즉시 주소에서 제거한 뒤 POST body로만 교환. 심사 세션은 학교 계정과 구분.
- 심사: 실무 35 / 편의 30 / 완성 20 / 창의 15, 항목 설명·정수 범위·합계·최종 확인, 저장 중 중복 클릭 차단, 서버 중복/만료 오류 표시. 결과에는 항목별 평균·평균 총점·유효 심사 수·공동 순위/수상 표시.
- HTML: 서버가 정제한 문자열만 `sandbox=""` iframe으로 표시. 스크립트·동일 출처 권한 없음. iframe 문서 CSP는 `default-src 'none'`에서 시작하며 외부 연결·폼·프레임을 차단. 원본은 별도 권한을 검사하는 첨부 다운로드.
- 교실: 서버가 계정의 반에 맞게 필터한 행사만 배너·공지판·트로피로 표시. 이동 가능한 구역 밖에 배치하고 충돌 지도는 변경하지 않음. 개최 취소/보관/행사 없음에 따라 객체 제거. 이벤트가 있는 동안 60초 및 화면 복귀 시 서버 상태 갱신.

## 실행한 브라우저 시나리오

명령: `npm run build` 후 `npx playwright test tests/competitions.spec.ts --reporter=list`.

1. 독립 MASTER·STUDENT 실제 계정과 두 외부 브라우저 세션: 반·대회 생성 → 개최 → 학생 템플릿 제출 → HTML 갱신 → 새로고침 → 안전 미리보기 → 무효 KEY → KEY 연결 → 91점 평가 확인·저장 → 중복/재사용 KEY 거부 → 결과 공개 → 보관 후 교실 안내 제거. 첫 통합 시나리오 통과.
2. 1920×1080 / 1440×900 / 1366×768 / 1280×720 / 390×844에서 긴 한국어 제목·설명·카드 가로 넘침 검사. 모바일 100점 확인 모달의 화면 내부 배치, 35점 초과 입력 거부, Escape 및 포커스 복귀, MASTER 모바일 메뉴 접근 검사. 두 번째 시나리오 개별 재실행 통과(13.1초).
3. 서버의 실제 접수 시작을 기다린 후 브라우저의 갱신 타이머만 앞당겨, 유휴 교실의 예정 → 접수 중 변경을 서버 응답으로 확인. 서버 시계나 대회 판정은 조작하지 않음.
4. 업로드 HTML의 script / onerror / iframe / form 제거, 빈 sandbox, 엄격한 CSP, 부모 창의 공격용 변수 미생성 검사. 소개서의 실제 iframe 제목 가시성 검사도 회귀에 포함.
5. 공개 화면의 `/api/config`, `/api/state`, `/api/login`, `/api/demo` 부팅 요청 없음. 외부 세션의 `/api/state` 401, 공개 응답에 학생 이메일·학생 내부 ID·비공개 프로젝트 목적 미포함. 실제 production 정적 파일을 사용하고 브라우저에서 모든 `/assets/**` 요청을 401로 차단해 공개 별도 번들의 동적 JS/CSS 로딩을 검증.

## 접근성 검사 범위

공개 심사 화면 및 모바일 확인 모달에 axe WCAG A/AA 자동 검사를 적용했다. 스크립트와 same-origin을 허용하지 않는 소개서 iframe은 의도적으로 독립된 불투명 출처다. axe의 기본 다중 프레임 `runPartial/finishRun`은 이 환경에서 시간 초과되어, 최종 검사는 같은 출처 UI를 검사하는 legacy 모드와 `iframes:false`를 사용한다. 접근성 검사를 위해 iframe의 보안을 낮추지 않았다. iframe 제목·정적 내용 가시성·CSP·스크립트 차단은 별도로 검증한다. 자동 검사는 모든 사용성이나 WCAG 적합성을 보장하지 않는다.

## 디자인 반복 개선

초기 심사 상세 화면은 긴 일정 헤더와 큰 고정 소개서 때문에 평가 입력까지 스크롤이 많았다. 실제 캡처 검토 후 선택 작품 화면의 헤더를 줄이고, 일정을 접을 수 있게 하고, 소개서를 300px(모바일 280px) 미리보기와 확대 버튼으로 바꾸며 평가 항목 바로가기를 추가했다. 동명이름 중복 밀도를 줄이기 위해 다른 사람 책상은 번호로 표시하고 캐릭터 이름표와 나의 책상 표시는 유지했다. 기본반 선택 해제는 자동 복귀 규칙 때문에 의미가 없으므로 기본반 명단은 읽기 전용으로 표시하고 반 이동 방법을 설명했다.

## 한계

로컬 production 정적 배포와 별도 공개 번들은 검증했지만, 이 파일만으로 Railway의 실제 Volume·HTTPS·사설 입구 게이트·외부 URL 연결까지 검증한 것으로 보지 않는다. 해당 배포와 게이트 검증은 운영 담당의 최종 보고서를 확인한다. 소개서 템플릿의 화면 설명 항목은 일반 텍스트이며, 미리보기에서는 이미지·외부 리소스가 제거된다. 스크린샷은 허용된 PNG/PDF 등의 결과물 파일로 따로 제출할 수 있으며, HTML 안 이미지 표시 기능은 제공하지 않는다. 학생 수준·심사자 모집 규모에 따른 실제 교육 운영 평가는 남아 있다.

## 최종 회귀에서 발견한 운영 화면 결함 수정

추가 회귀에서 반을 옮긴 학생의 ID가 대회 참가 명단에는 남아 있지만 편집 화면의 현재 반 체크박스에서는 숨겨지는 문제가 확인됐다. 현재 반의 재학생이 아닌 참가자를 명시적으로 표시하고, 출품 이력이 없으면 MASTER가 명단 정리를 선택한 뒤 저장하게 했다. 출품 이력이 있으면 기존 참가자를 제외하지 않고 원래 반 복귀 또는 대회 보관을 안내한다. 임시 출품작까지 보존되는 것을 새 브라우저 회귀로 확인했다.

390×844 교실에서 학생이 이미 입장한 뒤 대회가 개최되어 안내 줄이 추가되면, 터치 방향 패드가 하단 메뉴 아래로 밀리는 실제 결함도 재현했다. 게임 영역의 크기는 그대로여서 기존 ResizeObserver가 세로 위치 변화를 감지하지 못했다. 교실 컨테이너의 크기도 관찰해 안내 줄·도구 모음 줄바꿈으로 인한 위치 변경 후 패드 안전 여백을 다시 계산한다. 버튼 중심의 실제 hit target, 하단 메뉴 위 배치, 포인터 이동, 방향키 및 페이지 스크롤 고정을 함께 검사한다.

심사 종료와 결과 발표 시각이 다른 경우 서버는 두 시각이 모두 지난 뒤에만 결과를 공개한다. 브라우저 회귀의 대기 조건도 서버 응답의 `serverNow >= resultsAt`와 `JUDGING_CLOSED`를 함께 확인하도록 수정했다. 빠르게 실행되는 환경에서 정당한 409 응답을 테스트 실패로 오해하던 500ms 경계 경쟁을 제거했으며 서버의 제한은 변경하지 않았다.

이 변경을 포함한 `npx playwright test tests/competitions.spec.ts --reporter=list` 최종 표적 실행은 **3개 모두 통과(53.8초)**했다. 전체 제품 회귀 및 최종 운영 배포 결과는 상위 운영 보고서를 따른다.
