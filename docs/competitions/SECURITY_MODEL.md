# 반별 경진대회 백엔드 보안 및 운영 모델

검증 기준: `tests/competitions.test.ts`. 이 문서는 로컬 구현·검증 결과이며 실제 배포 여부는 최종 배포 보고서의 별도 증거를 확인해야 합니다.

## 권한과 데이터 경계

기존 계정·프로젝트·SQLite WAL·WebSocket을 보존합니다. 기존 사용자는 `class-학교ID-default` 기본반으로 해석하며 기존 사용자 JSON을 일괄 변경하지 않습니다. MASTER만 자기 학교의 반·학생 배정·대회를 관리합니다. 학생은 자기 반의 지정 대회만 조회·제출합니다. 제출 이력이 있는 운영 중 대회 참가자는 대회를 보관하기 전 반 이동을 차단합니다.

공개 페이지는 정확한 `/competition/UUID` 및 `/api/public/competitions/UUID/...` 경로만 학교 입구 접근 암호를 예외 처리합니다. 계정·학교·기존 `/assets/` 및 WebSocket의 접근 제한은 유지합니다. 별도 `/competition-assets/파일명`은 빌드 정적 자산만 제공합니다. Vite HTML과 신뢰할 수 있는 JS/CSS 내부 자산 경로를 이 접두사로 바꾸며 API 권한에는 영향을 주지 않습니다.

공개 API는 MASTER 로그인 쿠키가 있어도 계정 권한을 사용하지 않습니다. DTO 허용 목록으로 이메일, 학생·학교 ID, 참가자 목록, 프로젝트 원본·메모·비공개 피드백을 제외합니다.

## 제출과 동의

최종 제출에는 결과 URL 또는 결과 파일, 템플릿 또는 HTML 소개서, 안내된 공개 범위의 명시적 동의가 필요합니다. `consentPublic`은 현재 설정된 심사·전시 범위에 대한 동의입니다. 거부 상태는 초안으로 저장할 수 있습니다. 기본 범위는 심사자 전용입니다.

동의 당시 공개 범위와 실명 공개 설정을 제출 버전에 보관합니다. MASTER가 나중에 PUBLIC·실명 공개로 바꾸어도 기존 동의를 소급 확대하지 않으며 학생의 재제출이 필요합니다. 일반 공개에는 현재 PUBLIC 설정과 제출 시 PUBLIC 동의가 모두 필요합니다.

프로젝트 원본을 공개 DTO에 직접 연결하지 않습니다. 제출 시 필요한 소개 필드만 별도 스냅샷에 복사하며 이후 프로젝트 수정은 제출물을 변경하지 않습니다. 모든 수정·철회 버전과 revision 충돌을 검사합니다. 작품 수정은 100회로 제한합니다.

기한은 오프셋이 명시된 ISO 시각을 UTC로 저장하고 서버 시간으로 검사합니다. UI는 KST로 표시합니다. 개별 연장은 심사 시작 전 승인하며 심사 시작을 넘길 수 없습니다. 심사 시작 후 제출·철회·대회 설정 변경을 차단합니다. 첫 심사 단계 접근 또는 60초 점검에서 원자적으로 최종 제출 목록을 확정하므로 재시작 후에도 같은 버전을 심사합니다.

## HTML·파일

- 원본과 정적 미리보기를 분리합니다. `sanitize-html` 파서의 좁은 태그 허용 목록을 적용하고 모든 속성·CSS·URL·이미지·스크립트·폼·프레임을 제거합니다. 미리보기는 128KB 이하입니다.
- 프런트엔드는 `sandbox=""` iframe과 `default-src 'none'`으로 미리보기를 표시하며 사용자 HTML에 인증 쿠키·서버 비밀을 전달하지 않습니다.
- 원본 HTML 다운로드는 소유자·MASTER·해당 작품 범위의 유효한 심사자만 허용합니다. 일반 PUBLIC 동의로 원본 HTML 다운로드 권한이 생기지 않습니다.
- 결과 파일은 MASTER 확장자 목록, 실제 서명·UTF-8·정규 base64·파일명 경로/제어문자 검사와 파일당 5MiB 제한을 적용합니다. 소개서 HTML은 결과 파일 목록과 별개로 허용합니다. 업로드 요청은 14MB, 공개 심사 JSON은 16KB로 제한합니다.
- 기존 학교 합계 120MiB 저장 한도와 디스크 여유 검사에 경쟁 파일도 포함합니다. 저장·첨부·버전·알림은 같은 트랜잭션으로 처리합니다.
- ZIP을 풀거나 실행 파일을 실행하지 않습니다. 다운로드는 attachment, application/octet-stream, nosniff, sandbox CSP입니다. 악성코드 탐지 서비스는 연결하지 않았습니다. 실행 파일은 MASTER가 명시적으로 허용해야 합니다.
- 사용자 URL은 HTTP(S) 형식만 검사하며 서버에서 가져오지 않습니다. 접근성·내용의 안전성을 보장하지 않습니다.

## 심사 인증과 무결성

256비트 임의 KEY는 발급 응답에서 한 번만 보여 주며 DB에는 SHA-256 해시만 저장합니다. 링크는 `#judge=KEY` fragment를 사용하고 활성화 후 제거합니다. URL query·로그·Git에 KEY를 보관하지 않습니다.

SQLite 트랜잭션의 조건부 UPDATE로 KEY 활성화가 한 번만 성공합니다. 심사자는 대회·허용 작품에 한정된 별도 HttpOnly/SameSite=Strict 쿠키를 받습니다. 운영 COOKIE_SECURE 설정을 따르며 계정 로그인 권한은 생기지 않습니다. 회수·만료를 매 요청 검사합니다.

새 활성화와 점수 제출은 심사 종료에 닫힙니다. 기본 읽기 세션은 발표 예정 후 7일, 발급 후 최대 30일까지 유지하여 심사자 전용 결과를 읽을 수 있습니다. MASTER의 짧은 만료 지정은 그대로 적용합니다. 읽기 권한으로 마감 후 점수를 새로 제출할 수 없습니다.

KEY 시도는 IP당 180회/15분, 대회·IP당 60회/15분, 공개 API 600회/분, 심사자 점수 요청 120회/분으로 제한합니다. 공유 NAT의 30명 유효 KEY 활성화를 실제 API로 검증했습니다. 한 사람이 여러 KEY를 받거나 공유하는 것까지 완전히 차단할 수는 없으므로 발급 정책과 사용·중복 감사 기록을 확인해야 합니다.

점수는 정수 35/30/20/15 범위를 검사합니다. 대회·심사자·작품 UNIQUE 및 대회·심사자·요청번호 UNIQUE로 중복을 막습니다. 같은 idempotencyKey·내용의 재시도만 기존 결과를 반환하며 다른 내용·중복 최종 제출은 409입니다. 합계 대신 평균으로 순위를 계산하며 반올림하지 않은 정수 분수로 동점을 비교합니다. 완전 동점은 공동 순위, 최소 심사 수 미달은 수상 제외입니다.

MASTER만 미공개 집계를 볼 수 있습니다. 종료·발표 시각 이후 MASTER가 명시적으로 발표해야 학생과 허용된 외부 열람자에게 결과가 나옵니다. 개별 심사자 ID·점수·총평은 공개 결과에 포함하지 않습니다. 점수 수정·재심사는 구현하지 않았습니다.

## 데이터와 복구

`records`에 `competition-class`, `competition`, `competition-entry`, `competition-version`, `competition-final-entry`, `competition-freeze`, `competition-file`, `competition-extension`, `competition-audit`, `competition-notice`를 추가합니다. 별도 테이블은 `competition_judge_passes`, `competition_judge_sessions`, `competition_scores`입니다. 모두 school_id를 보관하며 기존 데이터를 삭제하지 않습니다. 앱 시작 CREATE TABLE IF NOT EXISTS로 추가합니다.

학교 내보내기는 다른 학교 점수를 제거하고 VACUUM으로 삭제 페이지를 정리합니다. 온라인 백업·학교 내보내기에서는 심사 KEY 해시와 세션을 제거합니다. 오프라인 CLI 복구도 계정·심사 세션과 심사 KEY를 제거하므로 과거 미사용 KEY가 복구 뒤 재사용되지 않습니다. MASTER는 KEY를 새로 발급해야 하며 기존 점수는 보존합니다. 일반 서버 재시작은 제출·점수·세션을 유지합니다.

이전 앱으로 되돌릴 때 새 테이블·records를 삭제하지 않습니다. 이전 버전은 알지 못하는 records 종류를 무시하므로 별도 스냅샷을 보관한 뒤 앱 버전만 되돌릴 수 있습니다. 이전 버전 운영 중에는 경진대회를 중단해야 합니다.

60초 점검은 24시간/1시간 마감, 접수 마감, 심사 시작을 기존 개인 알림에 연결합니다. 표식을 저장하여 재시작 때 반복하지 않으며 반을 이동한 학생에게 이전 반의 새 알림을 보내지 않습니다. 서버가 꺼졌던 동안의 과거 구간별 알림을 재생하지 않고 현재 단계만 안내합니다.

## 남은 범위

확정 점수 재심사·정정 이력 UI, 사용자 정의 배점, 심사 총평의 익명 공개 편집, 악성코드 검사, 외부 발송/이메일 알림, 장기 대회 세부 운영 정책은 포함하지 않았습니다. 실제 Railway HTTPS/WSS·Volume·외부 두 계정 접속은 최종 배포 보고서의 별도 증거를 확인해야 합니다.
